# FlyThings 六问：公开文档已查到的答案 + 剩余待验证

**2026-09-11 更新。** 原先这份是"发给开发者的提问稿"。实际去查了官方公开文档和 Ulanzi 官方仓库后，**六问里有四问半已经有明确答案，不需要问人**；剩下的几条是需要在真机上跑一次才能确定的行为，不是靠提问能解决的。

设备：Ulanzi TC002（FlyThings 平台代号 **Z21**），固件 `1.1.1`，MCU `V1.0.17`。

---

## 1. 按键事件 —— 已答（keycode 齐全），按压语义待真机

官方 TC002 仓库给出的就是 `KeyManager` 回调：

```cpp
KeyManager::getInstance().addKeyEventCallback([](int code){
  // E_KEYCODE_CLOCKWISE / ANTI_CLOCKWISE / KNOB_BUTTON
  // E_KEYCODE_LEFT_BUTTON / MIDDLE_BUTTON / RIGHT_BUTTON
});
```

- 旋钮左旋、右旋、旋钮按下、左键、中键、右键**六个 keycode 都有**，我们需要的"中键 + 旋钮切走"两种输入都覆盖到了。
- 回调只给一个 `code`。**短按/长按/连按没有单独事件**，要在应用里自己按时间戳区分（这对我们够用：只需要"按了一下"）。
- 屏保开启或息屏时还能不能收到按键 —— 文档没写，**需真机验证**。

## 2. 对外通信 —— 已答

- FlyThings 没有内置 HTTP 客户端，官方做法是引依赖包 **`curl-cxx`**（依赖包仓库里提供）。
- 必须放到工作线程：官方定时器文档明确"不建议在此函数中写耗时操作，否则将影响 UI 刷新"，TC002 仓库也强调 UI 线程不能阻塞。我们的设计正好要求网络失败不影响倒计时和铃声，所以网络调用一律异步、带超时、失败进本地队列。

## 3. 音频 —— 已答（循环播放要自己做）

Z21（即 TC002）用单参数音量的那套接口：

```cpp
sPlayer.play("/mnt/extsd/music/test.mp3");
sPlayer.stop();  sPlayer.pause();  sPlayer.resume();
sPlayer.setVolume(0.5);   // 0.0 ~ 1.0
```

- **文档没有循环播放参数**，也没有独立静音或"按键音/媒体音分开"的通道。
- 所以"一直响到按中键"的实现方式是：应用自己在播放结束回调或定时器里重新触发 `play()`；响 5 分钟后改成每 30 秒触发一次短音。这条不需要问厂商，是我们自己实现。

## 4. 部署与还原 —— 已答，而且是好消息 ✅

官方 TC002 仓库原文：

> 下载调试**不会固化**，断电后恢复。需要持久化时使用 `镜像编译` 生成 `update.img`，拷到 FAT32 格式 TF 卡根目录后插卡上电即可触发升级。

> 按住 USB-C 旁的复位按钮上电，会自动刷回官方固件。

三件事因此定了：

1. **可以先临时跑**：下载调试不固化，断电就回原样 —— 正好满足"先验证再决定"。
2. **持久化方式**：编译出 `update.img`，拷到 FAT32 的 TF 卡根目录，插卡上电升级。
3. **可以还原原厂**：按住 USB-C 旁的复位键上电即刷回官方固件。不可逆的风险解除。

仓库另有一条硬要求：**启动时必须设置防砖标志**，MCU 初始化要在 LED 刷新之前，UI 线程不能阻塞（否则升级界面会失败）。写应用时必须照做。

## 5. 掉电持久化与时钟 —— 已答

- 持久化用 `StoragePreferences`（`putInt/putString/...`，以文件形式存在 flash）。文档警告"请勿频繁写入，造成 flash 损坏"，容量通常"几百 KB 内"。我们只在状态切换时写一次绝对到期时刻，频率远低于危险线。
- 时钟源文档没写。但 FlyThings 是 **Linux 系统**，所以倒计时直接用 `clock_gettime(CLOCK_MONOTONIC)` 推进，系统时间（RTC/NTP 校准）只用来生成上报给 Mac 的 epoch 值。这样系统时间跳变不会改变本轮剩余时间。这条也不需要问人。

## 6. 屏幕 —— 已答

- 背光/开关屏：`BRIGHTNESSHELPER->screenOn()` / `screenOff()` / `setBrightness(0~100)`（0 不等于关屏）。
- **屏保有超时设置**，可以在工程属性或代码里设，**设为 `-1` 即关闭**；`EasyUIContext` 还能查询/开关屏保状态。倒计时页面把屏保关掉即可常亮。
- TC002 是 LCD，不存在 OLED 烧屏问题，长时间常亮主要考虑功耗和夜间亮度。

## 剩下真正不确定的（都要真机试，不是提问能解决的）

1. 屏保开启 / 息屏状态下 `KeyManager` 回调是否仍然到达。
2. 中键"短按"在实际固件上是否会连带触发原生的其它动作；连按去抖阈值取多少合适。
3. `sPlayer` 重复触发 `play()` 做循环铃声时，会不会有可听见的间隙；以及和系统按键音是否冲突。
4. 倒计时页关屏保后长时间常亮的实际功耗/亮度表现。

这四条的验证方式都是同一件事：**用"下载调试"模式临时跑一个 demo（断电即恢复），花十几分钟按一遍**。
