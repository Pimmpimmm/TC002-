# 关于 TC002 自定义 FlyThings 应用的六个技术问题

（可直接整段转发给开发者 / 技术群，无需额外背景）

## 背景

设备：Ulanzi TC002，固件 `1.1.1`，MCU `V1.0.17`，用 Ulanzi Studio `3.2.11` 管理。

我想做的东西：一个番茄钟——按一次中键开始 45 分钟专注，屏幕倒计时；到期后设备**本地**响铃并一直响，直到我按中键才切到 5 分钟休息；休息到期同样一直响，按中键才开始下一轮。其间通过局域网向我的 Mac 发一个**不含任何正文的**开始/结束事件，Mac 负责改我自己的日历忙碌状态。

已经确认过的前提（所以才来问自定义应用）：固件 `1.1.1` 的 MQTT 与 HTTP 接口都**抓不到原生 BUSY 页的进入、退出或旋钮切换事件**——真机接私有 broker 完整抓包 90 秒，期间反复物理操作原生 BUSY，只收到 retained 的 `status=online` 和启动时的 `getBase`；`/getToolsConfig` 只有静态配置（`enable/focusTime/relaxTime`），没有任何当前页面或剩余时间字段。所以打算改成跑自定义 FlyThings 应用，按键、倒计时、铃声全部在设备内做。

## 六个问题

1. **按键事件**：自定义应用里 `E_KEYCODE_MIDDLE_BUTTON (0x69)` 的短按、长按、连按是否都能稳定收到？旋钮左旋/右旋/旋钮按下分别对应哪些 keycode？应用在息屏或非前台时还能收到按键事件吗？

2. **对外通信**：自定义应用有官方可用的 HTTP 客户端吗，还是只能用裸 socket？官方推荐的"设备 → 局域网主机"通信方式是什么？能否设置连接超时和失败重试而**不阻塞 UI 线程**（网络不通时倒计时和铃声必须照常跑）？

3. **音频**：`AudioManager::playAudio()` 能否**循环播放、或一直播放到手动停止**？能否控制音量、能否独立于系统按键音单独静音？和原生的滴答音会不会冲突？

4. **部署与还原（最关心的一条）**：部署自定义应用是否等于**替换整机固件**——原厂的时钟、天气、BUSY、计时器这些页面是否会全部消失？**能否刷回原厂固件、官方恢复包从哪里获取？** 有没有办法用 Wi-Fi ADB 临时运行而不持久写入，方便先验证再决定？

5. **时间与掉电**：设备上如何持久化一个"绝对到期时刻"（有 NVS / 可写文件系统 / 掉电安全写入吗）？倒计时应该用哪个时钟——单调时钟、RTC、还是 NTP 校准后的系统时间？系统时间发生跳变时官方推荐怎么处理（我的要求是：重启后按原来的绝对到期时刻恢复，绝不能重新从 45 分钟开始算）？

6. **屏幕**：倒计时页面能否长时间常亮且不烧屏？到期响铃时能否强制点亮屏幕？有没有官方推荐的息屏/唤醒 API 和常亮策略？

## 我这边的参数（供参考）

专注 2700 秒、休息 300 秒；两个边界都是"一直响铃等人按中键"，不自动跳转；专注中按中键或旋钮切走 = 立刻结束本轮回空闲页。设备只向 Mac 发 `session_id / event / state / reason / started_at / focus_deadline` 这几个字段，不发任何聊天内容、不存任何凭据。
